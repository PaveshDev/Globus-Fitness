System Specification & Architecture Document

Globus Fitness: Autonomous Multi-Agent & WhatsApp Bot Architecture

Self-Regulating Membership Lifecycle, Automated Billing Verification, and Smart Proactive Reminders
Platform: Globus Fitness Club
Stack: React 19 + Node.js 24 + Neon PostgreSQL + Prisma 7
Communication: WhatsApp Business Cloud API
Architecture Pattern: Hierarchical Supervisor-Worker Multi-Agent

1. Executive Summary & Workflow Objectives

This document defines the architectural blueprint and operational mechanics for Globus Fitness Club's customer onboarding and subscription lifecycle. By combining a WhatsApp Business Cloud API bot with a specialized Hierarchical Multi-Agent System, the gym automates routine manual checks, payment validations, deadline enforcement, and proactive retention communications while maintaining strict administrative control.

Core Principles:
  • Admission-First Policy: No customer can access membership plans or workout facilities until their one-time admission fee (LKR 2,500) is paid and approved by an authorized administrator.
  • Deterministic Business Logic + Intelligent Agents: Critical date math (+30 days chaining, expiration dates) is computed deterministically in JavaScript/PostgreSQL, while AI agents handle conversational comprehension, receipt OCR data extraction, and exception escalation.
  • Self-Regulating Deadlines: 72-hour (3-day) registration cleanup prevents ghost records, and a 7-day plan payment threshold flags delinquent selections for administrative review.

2. Hierarchical Multi-Agent System Topology

The system follows a Supervisor-Worker topology. The Master Supervisor Agent governs the state transitions of every member profile, delegating specific domain tasks to 6 focused sub-agents:

[ CUSTOMER (Web / WhatsApp) ] <===> [ WHATSAPP CLOUD API GATEWAY ] || +-----------------------+ | MASTER SUPERVISOR AGENT| <===> [ NEON POSTGRESQL / PRISMA ] +-----------------------+ || +-------------------+----------------------+-------------------+-------------------+ | | | | | [ Agent 1 ] [ Agent 2 ] [ Agent 3 ] [ Agent 4 ] [ Agent 5 ] WhatsApp Concierge Admission Watchdog Receipt OCR & Admin Plan & Billing Renewal & Reminder (Conversations) (3-Day Auto-Purge) (Slip Validation) (Date Math) (Day-27 Watcher) | [ Agent 6 ] Delinquency Audit (7-Day Plan Unpaid)

3. Detailed Specifications of the AI Agents

🧠 Agent 0: Master Supervisor Agent (System Orchestrator) Master Orchestrator

Primary Function: Enforces the system-wide state machine, sequences agent tasks, monitors agent health, and commits verified state changes to PostgreSQL.

  • Input Triggers: Website registration event, incoming WhatsApp webhook message, scheduled cron heartbeat, Admin dashboard action.
  • State Management: Maintains customer states (REGISTERED_UNPAID → ADMISSION_PENDING_VERIFICATION → ADMISSION_APPROVED → PLAN_SELECTED_PENDING_PAYMENT → ACTIVE_MEMBER → PAYMENT_OVERDUE).
  • Enforcement: Prevents out-of-order execution (e.g. rejects plan assignments if admission status is not approved by admin).
💬 Agent 1: WhatsApp Concierge & Interaction Agent Worker Agent

Primary Function: The human-facing conversational interface responsible for inbound message comprehension, dynamic template generation, and interactive guidance.

  • Key Tasks:
    1. Sends immediate welcome greeting with bank transfer instructions upon website account creation.
    2. Ingests payment slips (images/PDFs) uploaded by the user and forwards raw assets to Agent 3.
    3. Presents plan selection prompts (1 Month @ LKR 2,500, 3 Months @ LKR 7,000, 6 Months @ LKR 12,000, Annual @ LKR 25,000) once admission is approved.
    4. Dispatches scheduled renewal reminders (Day 27) and confirmation receipts.
⏱️ Agent 2: Admission Watchdog Agent (3-Day Policy) Timer / Janitor

Primary Function: Cleans up abandoned registrations where customers registered on the web but failed to submit admission payment within 72 hours.

  • Trigger: Hourly scheduled sweep.
  • Logic: Identifies records in REGISTERED_UNPAID state where createdAt < (now - 72 hours) with zero payment proof.
  • Action: Dispatches a courteous farewell notification via WhatsApp ("Your registration window has expired. You may re-register anytime") and purges the pending record from the database to release the phone number and NIC.
🔍 Agent 3: Receipt OCR & Admin Verification Agent Vision / OCR / Validation

Primary Function: Parses bank deposit slips or transfer receipts using multimodal vision OCR, extracts transaction metadata, and submits an actionable review card to the Gym Admin.

  • Extraction Fields: Bank Name, Transaction Ref / Trace ID, Transfer Amount, Date & Time, Sender Account Name.
  • Validation Checks: Confirms transfer amount matches required fee (e.g. LKR 2,500). Verifies transaction reference is unique (anti-fraud duplicate slip check).
  • Admin Dispatch: Automatically queues the image with pre-filled verification data in the Admin Dashboard. Once the Admin clicks "Approve & Unlock", this agent triggers the Supervisor to update the member's status.
📅 Agent 4: Plan Subscription & Billing Calculation Agent Deterministic Math

Primary Function: Executes exact date arithmetic for gym subscriptions and ensures continuous coverage without losing paid days.

  • Initial Plan: Sets startDate = registrationDate (or activation date) and endDate = startDate + 30 days.
  • Rolling Renewal: When extending an existing subscription, sets newStartDate = previousEndDate and newEndDate = previousEndDate + 30 days, guaranteeing that early payments don't penalize the customer.
🔔 Agent 5: Subscription Renewal & Day-27 Reminder Agent Proactive Monitor

Primary Function: Monitors active members and drives membership retention through timed payment reminders.

  • Trigger: Daily scheduled check at 08:00 AM.
  • Condition: (subscription.endDate - today) === 3 days (the 27th day of a 30-day billing cycle).
  • Action: Commands Agent 1 to dispatch a reminder message indicating exact renewal amount, banking details, and the due date.
⚠️ Agent 6: Delinquency & Grace Period Escalation Agent Audit / Escalation

Primary Function: Enforces the 7-day payment window for customers who have selected a membership plan but have not completed payment.

  • Condition: Status is PLAN_SELECTED_PENDING_PAYMENT for > 7 days without receipt submission.
  • Action: Marks status as PLAN_PAYMENT_OVERDUE and escalates an alert directly to the gym manager for follow-up or deactivation.

5. Exception & Timeout Safety Net

Scenario Triggering Condition Agent Responsible Enforced Action
Abandoned Registration User registers online but does not submit admission payment within 72 hours (3 days). Agent 2
(Admission Watchdog)		 Sends final expiry notice on WhatsApp. Deletes pending user record from database so phone number and NIC can be used again.
Unpaid Plan Selection Admission paid and approved, but member fails to pay chosen plan amount within 7 days. Agent 6
(Delinquency Agent)		 Sets status to PLAN_PAYMENT_OVERDUE. Dispatches reminder warning to user and logs priority ticket in Admin Dashboard.
Duplicate or Fraudulent Slip User uploads an already-used slip or mismatched transfer amount. Agent 3
(Receipt OCR Agent)		 Detects duplicate transaction reference. Flags slip as SUSPICIOUS_REVIEW for Admin inspection. Prevents automated unlocking.

6. Technical Implementation Stack

  • WhatsApp Gateway: Official Meta WhatsApp Cloud API via Express Webhook router (/api/webhooks/whatsapp).
  • Storage: PostgreSQL on Neon with Prisma 7 ORM and Prisma Client driver adapter.
  • Receipt Processing: Multimodal Vision (Gemini 2.5 Flash / Vision API) for high-accuracy OCR extraction on Sri Lankan bank receipts (BOC, Commercial Bank, Sampath, HNB, FriMi).
  • Background Jobs & Cron: Node.js scheduled workers for the 3-day admission watchdog (hourly) and 27th-day reminder agent (daily at 08:00 AM).
